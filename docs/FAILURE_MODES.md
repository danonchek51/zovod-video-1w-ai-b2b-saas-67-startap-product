# FAILURE_MODES.md — типовые отказы, как их ловить и как откатывать

> Документ перенесён из рабочей среды монтажа и обобщён: названия проекта, клипов и людей заменены плейсхолдерами. Проверенные факты и числа сохранены.

Чек-лист до и после каждой мутации. Источники: практика проекта + разбор чужих отчётов по агентским пайплайнам. Каждая строка — **признак → детект → профилактика → откат**.

- [ ] Сделана **точка отката** (`python tools/checkpoint.py save`).

## 1. Склейка посреди фразы

**Признак:** обрыв слова, рваная речь.
**Детект:** граница фразы в транскрипте не совпадает с кадром склейки; на waveform видна речь в кадре склейки.
**Профилактика:** резать по границе предложения/придаточного; оставлять **2–6 кадров** запаса речи.
**Откат:** продлить исходящий клип до конца клаузы, перерендерить.

## 2. Склейка посреди вдоха

**Признак:** срезанный вдох, «оборванная» комната.
**Детект:** вдох рядом с кадром склейки; скачок амплитуды.
**Профилактика:** не резать на вдохе; держать **3–8 кадров** вокруг дыхания; при необходимости резать звук отдельно от картинки (J/L-cut).
**Откат:** вернуть дыхание, обрезать картинку отдельно.

## 3. Ошибка в расчёте кадров

**Признак:** таймлайн короче/длиннее брифа; невозможные диапазоны.
**Детект:** расхождение ожидаемой и фактической длительности; отрицательный source-range.
**Профилактика:** **все длительности в кадрах** по фактическому fps таймлайна (`tl.GetSetting('timelineFrameRate')`), не хардкодить 24/25; проверять до записи.
**Откат:** пересчитать от источника, пересобрать диапазон.

## 4. Скачок под тем же углом

**Признак:** человек «прыгает» в кадре без смысла.
**Детект:** один и тот же источник/ракурс, похожая композиция, разрыв положения.
**Профилактика:** перед удалением тишины — смена зума, кропа, рефрейма, движения или B-roll.
**Откат:** вернуть удалённый материал.

## 5. Кадр-вспышка / нулевой зазор

**Признак:** чёрный кадр на один кадр, повтор, щелчок в звуке.
**Детект:** `verify_timeline.py` (дыры/наложения) + просмотр рендера на каждой склейке.
**Профилактика:** проверять всю арифметику in/out и `recordFrame`; после каждой партии — структурная проверка.
**Откат:** закрыть зазор, убрать дубль-кадр, перерендерить участок.

## 6. Преждевременный уход

**Признак:** мысль/реакция осталась недоговорённой.
**Детект:** склейка раньше завершения клаузы или пика реакции.
**Профилактика:** требовать признак «мысль дозвучала»: завершённая клауза, удержание реакции или разрешение действия.
**Откат:** продлить исходящий план на 6–24 кадра.

## 7. Избыток переходов

**Признак:** dissolves и wipes на обычных склейках, «эффект ради эффекта».
**Детект:** счётчик переходов в минуту; переход на реплике.
**Профилактика:** по умолчанию — **прямая склейка**. Переход — только для времени, места, тона или явного VFX.
**Откат:** заменить прямой склейкой.

## 8. Разрыв звуковой непрерывности

**Признак:** прыгает room tone, музыка входит/выходит рывком, эффект «висит».
**Детект:** разрыв спектра/амплитуды; SFX без визуального мотива.
**Профилактика:** держать шумовую подложку, кроссфейдить музыку, мотивировать каждый эффект.
**Откат:** добавить подложку/кроссфейд или убрать немотивированный эффект.

## 9. Эффект перекрывает смех или пуант

**Признак:** шутка не сработала, публику не слышно.
**Детект:** тело SFX перекрывает речь/смех/вдох.
**Профилактика:** отклонять синтетический SFX при перекрытии; исключения — tape-stop, «динь», печать как акцент пуанта.
**Откат:** сдвинуть эффект за смех, снизить или убрать.

## 10. «Эффект из библиотеки»

**Признак:** звук слишком чистый, оторван от комнаты.
**Детект:** SFX доминирует над боевым слоем; нет совпадения по характеру помещения; одинаковый тембр повторно.
**Профилактика:** уровень по перспективе кадра; реальный фоли вместо синтетики для физических предметов.
**Откат:** заменить записью или убрать.

## 11. Сцена-детектор как монтажёр

**Признак:** механические склейки на каждом визуальном изменении.
**Детект:** склейки не совпадают со сюжетными битами или логикой транскрипта.
**Профилактика:** детектор — **свидетельство**, не решение; каждая склейка нуждается в обосновании по биту.
**Откат:** пересобрать по утверждённой сюжетной карте.

## 12. Доверие маркеру без проверки

**Признак:** событие поставлено не туда.
**Детект:** кадр на маркере не показывает ожидаемого.
**Профилактика:** проверять рендер-кадр на каждом опорном маркере.
**Откат:** пере-вывести маркер из транскрипта, зрения или ручного кадра.

## 13. Устаревший анализ

**Признак:** правка опирается на старый отчёт.
**Детект:** отчёт потерял актуальность; клипы переимпортированы/перелинкованы.
**Профилактика:** перед редакционными рекомендациями — **свежий прогон**; обновлять только изменившиеся модальности.
**Откат:** перегенерировать; не переиспользовать молча.

## 14. Мутация исходников / прокси

**Признак:** оригинал изменён, появились незапланированные прокси.
**Детект:** изменилась контрольная сумма, релиз события relink.
**Профилактика:** исходники иммутабельны; прокси/релинк/транскод — **только по явному одобрению** и по совпадению манифеста.
**Откат:** восстановить из бэкапа/чек-суммы; прокси создавать заново — с одобрения.

## 15. Мутация проекта Resolve «руками»

**Признак:** правки `.drp`/проектной базы вне API.
**Детект:** файлы проекта изменились помимо API.
**Профилактика:** **проект Resolve — только через MCP**. Для операций вне API (патчинг базы Fairlight) — только при выключенном Resolve, с бэкапом и явным одобрением.
**Откат:** восстановить проект из точки отката/бэкапа.

## 16. DRX: флаг «True» ≠ грейд применён

**Признак:** `ApplyGradeFromDRX` вернул `True`, картинка не изменилась (или Resolve упала на «кривом» DRX).
**Детект:** флаг бесполезен — сверять `GetToolsInNode(i)` по каждой ноде и сравнивать рендер «до/после» (RMS).
**Профилактика:** генерировать с `resolveVersion: '21'`; в песочнице проверять только граф (в свежем проекте экспорт кадра даёт чёрный кадр); визуальную сверку делать в рабочем проекте; всегда писать label в DRX, чтобы ноду можно было опознать.
**Откат:** `Graph.ResetAllGrades()` + переприменение рабочего грейда; после краша — пересборка таймлайна целиком (`CreateTimelineFromClips`) и переприменение грейда.

> Статус на 31.10.2026: вендорнутый кодек (`vendor/drx-codec`) **принят нашей 21.1.1** — проверены primary, power window и 2-нодный DRX, краша нет. Самописные DRX, сделанные раньше, Resolve 21.1.1 роняли — пользоваться кодеком, не самописью.

## 17. «Готово» без измерения

**Признак:** отчёт без чисел.
**Детект:** в отчёте нет ни одного измеренного значения.
**Профилактика:** каждое утверждение об эффекте — с числом (RMS, LUFS, % клиппинга, % пересветов, кадровая раскладка).
**Откат:** переделать отчёт; явно писать «не проверено».

## 18. Слишком много слоёв правки за раз

**Признак:** непонятно, что именно ухудшилось.
**Профилактика:** один этап = один тип правки (цвет / монтаж / звук / графика). Каждый этап — отдельная точка отката и отдельное одобрение.

## 19. Стерео декодировано как моно — таймкоды врут вдвое

**Признак:** файл «вдвое длиннее оригинала», голос звучит «полуспидом», все
таймкоды не сходятся с картинкой, а монтаж разъезжается.

**Детект:** `ffprobe` говорит `channels=2`, а файл получился моно с длиной
×2. Сверять: `len(сигнал) == 48000 × duration`. Если нет — декодирование идёт
с чередованием каналов.

**Профилактика:** декодировать в моно **всегда** с `-ac 1` (или `pan=mono|c0=cN`).
Каждый замер — на правильной оси времени; любые старые числа, посчитанные на
сломанном файле, считать недействительными и переделывать.

**Откат:** переделить замеры на корректном файле. Пересобранный звук класть
на таймлайн **только** после проверки `ffprobe` (число кадров/каналов/длина).

> Проверено 01.11.2026 на тестовой сборке: WAV без `-ac 1` прочитан как
> моно 130,56 с вместо стерео 65,28 с; сломанный файл попал на таймлайн, и все
> измерения по нему (уровни, паузы, таймкоды) оказались неверными вдвое.

## 20. Шумоподавление убивает комнату и слова

**Признак:** в «паузах между репликами» пропадает звук, отдельные слова
проваливаются, зритель ждёт продолжения диалога. В оригинале при этом —
ровный фон.

**Детект:** сравнить **оригинал** и обработанный файл по полам (10-й
перцентиль оконной RMS 40 мс) и пословно (faster-whisper + RMS по словам).
Если в оригинале окон тишины (< −60 dBFS) **0**, а в обработке десятки — виновата
обработка, а не запись.

**Профилактика:** нейросетевое шумоподавление (`arnndn`/RNNoise) на разговорном
материале применять не бездумно: оно режет комнату на 15–30 дБ и душит
отдельные слова. Мягкая замена — `afftdn=nr=8:nf=-50`. Слышимость чинить
**адаптивным** подъёмом (потолок +6…+9 дБ, гейт от шумового пола), а не общим
gain.

**Откат:** пересобрать клип **из оригинала** (исходники — только чтение), а не
подгонять уже обработанный файл.

> Проверено 01.11.2026: RNNoise съел ≈20 дБ комнаты на CLIP_A (−45,30 → −65,73 dBFS);
> в оригинале тишины < −60 dBFS не было нигде. Клип пересобран из оригинала,
> «дыры» ушли (976 окон тишины → 0).

## 21. Resolve упал — модалка блокирует API, но проект цел

**Признак:** MCP-вызовы к Resolve виснут и отваливаются по таймауту; на экране
диалог «Отчет о проблемах DaVinci Resolve» с кнопками «Больше не спрашивать» /
«Игнорировать» / «Отправить».

**Детект:** процесс `Resolve` жив, но окно — модальное, поэтому API не отвечает.
Ищите в `%APPDATA%\Blackmagic Design\DaVinci Resolve\Support\logs\ResolveDebug.txt`
и `crash_archive.txt` строку `CRASH DUMP` и последнюю строку `ERROR` перед ней —
это и есть причина.
macOS: `%APPDATA%` не существует — логи искать в `~/Library/Logs/Blackmagic Design/…`.

**Профилактика (что реально работает):**
- Resolve рисует интерфейс через **Qt**, поэтому его кнопки **не видны** через Win32
  (`EnumChildWindows` отдаёт 0 элементов) — нажать «Игнорировать» программно
  нельзя. Единственный путь — **снять процесс и запустить заново**:
  `python tools/dismiss_dialogs.py` (сам снимает модальные окна и перезапускает
  Resolve; на macOS — через AppleScript System Events).
- Проект при этом **не теряется**: Resolve автосохраняет. Проверяйте
  целостность базы, не паникуя:
  `%APPDATA%\Blackmagic Design\DaVinci Resolve\Support\Resolve Project Library\Resolve Projects\Users\guest\Projects\<Проект>\Project.db`
  → `PRAGMA integrity_check` через `sqlite3` (скрипт `project_db_check.py`).
  macOS: тот же путь под `~/Library/Application Support/Blackmagic Design/…`.
- Если база цела — **импорт `.drp` не нужен**, достаточно открыть проект заново.
- Держите свежий `.drp` (`ExportProject`) — это страховка на случай, если
  автосохранение не успело.

**Откат:** `ExportProject` → `ImportProject` из последнего `.drp`; либо
`python tools/checkpoint.py restore` + `.drp`.

> Проверено 01.11.2026 на тестовой сборке: краш в 16:10:49, последний save —
> 16:10:40, `Project.db` цел (`integrity_check: ok`), проект открылся без
> единой потери (таймлайн, 18 маркеров, все 66 медиа-ссылок живы). Причина —
> **DNN-движок не нашёл модель** внутри `plugins\e4a498a3….bin` в портативной

> То есть это **дефект упаковки сборки**, а не наши правки.

## 22. `AddMarker` вернул False, а маркер нужен

**Признак:** `tl.AddMarker(...)` молча возвращает `False`, маркер не появляется.
При этом `tl.DeleteMarkerAtFrame(...)` работает — маркер удаляется, и его уже
не вернуть.

**Причина:** в Resolve 21.1.1 порядок аргументов
**`AddMarker(frameId, color, name, note, duration)`** — `color` идёт
**вторым**, не третьим. Вызов `AddMarker(frame, name, "Blue", 1, "")` молча
не создаёт маркер. Тип `color` — строка (`"Blue"`, `"Green"`, `"Orange"`, …).

**Профилактика:**
- всегда сверяться с `.pyi`: `search_scripting_api` по `AddMarker` даёт точную
  сигнатуру (`def AddMarker(self, frameId: int, color: MarkerColor, name: str,
  note: str, duration: int, customData: str | None=None) -> bool`);
- после `DeleteMarkerAtFrame` **сразу** проверять `GetMarkers()`, что маркер
  создан, иначе он потерян;
- правильный вызов: `tl.AddMarker(96594, "Blue", "БЛОК 4 · <МЕСТО>", "", 1)`.

**Откат:** если маркер уже удалён и `AddMarker` не работает — пересобрать
маркер из `.drp` (или поставить вручную в UI).

> Проверено 02.11.2026 на тестовой сборке (CLIP_B/CLIP_C): маркер «БЛОК 4 ·
> <МЕСТО>» был удалён и не создан; восстановлен после уточнения сигнатуры.

## 23. `AppendToTimeline` с `mediaType="audio"` ставит не то

**Признак:** аудио-айтем встаёт на A1, но с **той же позицией и полной
длиной видео**, а не с заданными `startFrame`/`endFrame`/`recordFrame`.
Для CLIP_B (видео 2828 кадра, аудио 2613) получилось: A1 = 2828 кадров с
95917 вместо 2613 с 96132 — рассинхрон 215 кадров.

**Причина:** `mediaType="audio"` в этой связке Resolve **игнорируется** для
клипов, у которых есть видео-дорожка: Resolve создаёт **линкованный** звук
(длиной по видео) и ставит его в начало видео-айтема.

**Что работает:** отдельный **аудио-файл** (WAV/AIFF без видео) в медиапуле
и `AppendToTimeline` с `mediaType="audio"` (или вовсе без него):

```python
res = mp.ImportMedia(r"<ПАПКА_АУДИО>\CLIP_B_audio.wav")   # строка, не список!
mp.AppendToTimeline([{"mediaPoolItem": item, "startFrame": 0,
                       "endFrame": 2613, "trackIndex": 1,
                       "recordFrame": 96132, "mediaType": "audio"}])
```

`ImportMedia` в 21.1.1 принимает **строку пути** (`ImportMedia([{...}])`
возвращает `None` и ничего не импортирует).

**Профилактика:** после вставки всегда сверять `GetStart()/GetEnd()` и
`GetSourceStartFrame()` каждого нового айтема с расчётными; не полагаться на
`mediaType` для аудио.

## 24. Массовая перезапись файлов обнулила 119 скриптов

**Признак:** после «простой» операции по снятию BOM все `.py` в папке проекта
стали **нулевой длины**; скрипты перестали работать.

**Причина:** в одном выражении файл сначала открывался на запись
(`open(f,'w')` — файл усекается!), а потом читался:

```python
# ТАК Ломает файлы:
io.open(f,'w').write(io.open(f, encoding='utf-8-sig').read())

# ТАК правильно: сначала прочитать в переменную, потом писать:
s = io.open(f, encoding='utf-8-sig').read()
io.open(f,'w',encoding='utf-8',newline='').write(s)
```

**Профилактика:**
- никогда не открывать файл на запись до того, как прочитан его старый
  содержимое; в списковых выражениях порядок вычисления легко перепутать;
- перед массовой операцией по файлам — `python tools/checkpoint.py save` (или копия);
- **точка отката спасла проект:** 131 из 137 скриптов восстановлены из
  `stage24_pre_clip_bx_cut__20261102_094829.zip` (точки отката — zip-архивы, а
  не папки; `.py` лежат в корне архива).

**Откат:** `zipfile.ZipFile(archive).read(name)` → запись в нужный путь.

> Проверено 02.11.2026 на тестовой сборке: ущерб закрыт восстановлением из
> архива точки отката; шесть файлов, созданных после архива, восстановлены
> вручную.

## 25. BOM в `.py` ломает `exec` внутри Resolve

**Признак:** скрипт, переданный в Resolve через `exec(compile(open(path,
encoding="utf-8").read(), ...))`, падает с
`SyntaxError: invalid non-printable character U+FEFF`.

**Причина:** файл сохранён с UTF-8 BOM (UTF-8-SIG). `compile()` не терпит
BOM в начале исходника.

**Профилактика:** читать исходники для `exec` как `encoding="utf-8-sig"`;
при записи скриптов на диск проверять первые байты (`b'\xef\xbb\xbf'`) и
перезаписывать без BOM — но **сначала прочитав** (см. §24).
