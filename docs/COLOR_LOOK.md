# COLOR_LOOK.md — грейд, LUT, DRX и контроль качества картинки

Ветка «дать материалу вид». Грейд — не «на глаз красивее», а числа: чёрная точка,
контраст, насыщенность, шум теней, зерно.

Читай параллельно `docs/RESOLVE_RECIPE.md` — половина проблем здесь не творческая,
а API-уровневая.

---

## 1. Сначала измерить референсы, потом грейдить

Прогони `skills/davinci-resolve-workbench/scripts/media_probe.py` по каждому референсу и сними четыре числа на файл:

* **чёрная точка** (p01) — на чём стоят тени;
* **свет** (p99) — где потолок;
* **средняя насыщенность**;
* **шум теней** (std ниже p10).

Ориентиры для «плёночного» вида:

| Параметр | Ориентир | Смысл |
|---|---|---|
| Чёрный уровень | 0,02–0,05 с холодным оттенком | тени не в ноль, у тени есть цвет; в измерениях референсов ≈ 209° (холодный сине-зелёный) |
| Контраст (p99 − p01) | 0,50–0,65 | выше 0,85 — жестко, начинает «перетирать» полутона |
| Насыщенность | средняя 0,22–0,30 | 0,17–0,22 в референсах; выше 0,45 — «трейлерный» вид |
| Зерно | ≈ 0,17–0,22 % на клипах, ≈ 1,8 % на ключевом кадре | очень мелкое зерно в нижней границе — безопасный выбор |

Назови доминирующие комплементарные пары (например, тил/нави ↔ янтарь, маджента/розовый
↔ фиолетовый/синий). Конфликт между референсами разрешает **тот кадр, который является
цветовым ключом** (обычно стоп-кадр).

## 2. Проектирование LUT

Сначала трансформация в numpy (быстро итерируется), потом emit `.cube` и **сверка
cube против numpy** — расхождение недопустимо.

Опорная таблица для семейства «пыльно-розовый / тил» — это **шаблон**, адаптируй под
свою задачу и проверяй каждый якорь после генерации:

| Вход | Ожидаемый выход | Зачем |
|---|---|---|
| чёрный (0,0,0) | ≈ (0.002, 0.000, 0.007) | поднятые холодные тени |
| красный (1,0,0) | ≈ (1.0, 0.77, 0.91) | основной цвет кожи → пыльно-розовый, sat ≈ 0.24, hue ≈ 337° |
| зелёный (0,1,0) | ≈ (0.54, 0.95, 0.80) | зелень/циан → тил |
| синий (0,0,1) | ≈ (0.35, 0.68, 1.0) | небо/тени → холодный синий |
| белый (1,1,1) | ≈ (0.94, 0.92, 0.98) | света остаются чуть холодными, не выбиты |

Правила, которые стоят денег:

* **Красный — самая быстро меняющаяся ось в `.cube` для Resolve.** Плоский индекс:
  `(b*N + g)*N + r`. Индексация вида `lut[g,r,b]` меняет R и B местами и молча портит
  грейд (на это ушёл целый цикл отладки).
* **WB и экспозиция живут внутри LUT.** `SetCDL` через API применяет свою кривую
  (измерено ≈ `y = 1.19·x^0.196`) и выбивает картинку — поэтому для вида проекта CDL
  не используется, а сдвиг CDL применяется позже в офлайн-посте.
* LUT ставится в папку LUT Resolve (`docs/ENVIRONMENT.md` §5) и подключается как
  `MCP\Name.cube`.
* Генерировать: `python tools/color/make_luts.py` (и `make_luts_v2.py` для второй
  версии look).

## 2.1. Быстрый путь: грейд целиком в LUT

Проверено на живом проекте (56 клипов, 42 цвета, 3840×2160, 25 fps, Resolve 21.1.1):
**весь цветовой грейд — одна 3D-LUT на клип, один вызов API на клип, ноль крашей.**

Порядок действий:

1. **Спецификация CDL** (JSON) на каждый клип или на каждый блок:
   `Slope`, `Offset`, `Power`, `Saturation` — подогнанные под статистику материала
   (её снимает `media_probe.py`) и под целевую кривую блока.
2. **Сборка .cube**: `python tools/color/make_cdl_luts.py --cdl spec.json --out luts`
   (красный — самая быстро меняющаяся ось, `make_cdl_luts.py` пишет по стандарту).
3. **Самопроверка файла**: `python tools/color/verify_lut.py --cube luts/X.cube --cdl spec.json --key K`.
   Расхождение с CDL выше 0,08 — брак файла. Инструмент отдельно сообщает, если
   переставлены R и B (это самая дорогая ошибка: картинка не красная, но не та).
4. **Установка в Resolve**: кубы копируются в `…\DaVinci Resolve\Support\LUT\`
   под ASCII-именами (кириллица в путях к API небезопасна), затем `RefreshLUTList()`.
5. **Накат**: `tools/color/apply_lut_grade.py` — батчами, с чтением обратно по
   каждому клипу. Клип ищется по (трек, старт) **и имени**, потому что переход может
   иметь тот же стартовый кадр.
6. **Проверка** (см. § «Проверка грейда»).

Три правила, которые стоили цикла отладки:

* `SetLUT` принимает **только** путь внутри папки LUT Resolve; абсолютный путь в
  другое место возвращает `False`;
* `RefreshLUTList()` — **после** копирования кубов, не до;
* изменённый на диске куб читается заново только после `SetLUT(1, "")`.

### Проверка грейда

Флаг «применилось» ничего не значит. Проверка — A/B-рендер одного кадра:

| что | как | норма |
|---|---|---|
| грейд влияет на картинку | рендер кадра с LUT и без него, разница по пикселям | MAE > 0,02 и изменено > 90 % пикселей |
| применён именно тот грейд | к кадру «без LUT» применить ту же математику и сравнить с кадром «с LUT» | MAE ≤ 0,01 (остаток — квантование 33³ и сжатие H.264) |
| восстановление точное | снять LUT, поставить обратно, отрендерить снова | MAE = 0,0000 (бит-в-бит) |
| нет красного каста | средний RGB кадра: R − max(G, B) | ≤ 0,05 для нейтральных блоков |

Отрицательный результат тоже результат: если MAE «с LUT / без LUT» = 0, значит рендер
не несёт грейд — и никакая другая проверка это не покажет.

## 3. Итерировать look офлайн, а не в Resolve



Офлайн-цикл в 10–50 раз дешевле рендера:

1. `ffmpeg -i src -vf "lut3d=file=<copy>.cube" ...` — **сначала скопируй cube на путь
   без двоеточия**, парсер фильтра ломается на букве диска.
2. numpy-проход для glow (bright-pass + blur + screen), зерна и виньетки.
3. Ту же самую CDL-математику применить в финальном посте, чтобы превью и финал
   совпадали численно.

**Glow** — это bright-pass-размытие, **прибавленное** к источнику, а не глобальная дымка:
порог высокий (выживают только источники и блики), радиус умеренный, blend низкий.
Иначе получится «молочный туман», который плоско выбивает картинку.

**Виньетка** — мягкое радиальное затухание, сила ≈ 0,20 на радиусе ≈ 1,05, в виде
`1 - strength * clip((d - 0.42) / 0.75, 0, 1) ** 1.7`, где `d` — нормированная
эллиптическая дистанция. Делать в Fusion (EllipseMask + Merge/EffectMask) в этой сборке
не вышло — держи виньетку в пост-проходе.

Превью отправляй заказчику **до** того, как трогать Resolve.

## 4. Сборка цепочки в Resolve

### Вариант A — один Color-узел с LUT

```python
ti.GetNodeGraph(1).SetLUT(1, "MCP\\Name.cube")
```

Узлов цветокора через API не создать (`AddNode`/`AddSerial`/`AddParallel` отсутствуют),
поэтому весь трансформат кодируется в LUT.

### Вариант B — DRX-файл (многоузловой грейд)

`ApplyGradeFromDRX(path, 0)` работает **не всегда и опасно**: на клипах, перекрытых
переходом, он **роняет Resolve** (воспроизведено 4 раза за одну сессию: V2@93179,
V1@90309, V1@93285, V1@93285 C0141_cut). На клипе без перехода применяется, и Resolve
рапортует тулы `Primary Balance`, `Power Windows`, `Log Grade`.

Сборка DRX: спецификация (`examples/drx_spec.example.json`) → `node tools/color/make_drx.js
spec.json out.drx` → применение в Resolve.

**Две ловушки:** `ApplyGradeFromDRX` возвращает `True` и тогда, когда картинка не
изменилась; на клипе под переходом он не возвращает ничего — он убивает программу.
Всегда сверять `GetToolsInNode(i)` **и рендер**, а не флаг; на рабочем таймлайне
многоузловой DRX накатывать **вручную в Color page**, не через API.

> Практический вывод: **весь грейд, который можно выразить одной кривой, делается LUT'ом.**
> API не умеет создавать узлы — многоузловой грейд через API недоступен в принципе.

### Fusion-комп

Цепочка `MediaIn → Glow → FilmGrain → MediaOut`. Соединять по **имени** входа
(`"Input"`, `"Background"`, …), никогда по индексу.

Параметры, давшие одобренный вид:

* **Glow** — Blend 1.0, Low 97, High 100, Glow 0.12, XGlowSize 4, YGlowSize 4,
  Passes 1, ColorScale 1, Alpha 1, фильтр `Fog Glow`.
* **FilmGrain** — Blend 1.0, MasterStrength 0.03, MasterXSize 1.0, MasterYSize 1.0,
  MasterRoughness 0.5, Monochrome 1, Randomize 1, Complexity 1.

Проверяй комп **рендером одного кадра**, а не «по параметрам».

> Fusion-комп не попадает в экспорт кадра — рендерится только цветовая ветка. Зерно
> и текстура видны только в рендер-джобе. Если «на превью зерна нет, а в финале есть» —
> это не баг, это разница каналов проверки.

## 5. Стабилизация

`ti.Stabilize()` — единственный доступный механизм, и его эффект **не читается через
API** (`GetProperty("Stabilization")` остаётся `False`). Проверять на отрендеренном
результате:

```bash
python skills/davinci-resolve-workbench/scripts/frame_qc.py motion \
    --src source.mov --graded render.mp4 --start 200 --count 40
```

Сравнивай один и тот же диапазон кадров в обоих файлах. Обычно камера в движении даёт
падение средней разницы между соседними кадрами на 30–50 %; если в кадре доминирует
собственное движение объекта — падение меньше, и это ожидаемо, а не отказ.

## 6. Пороги контроля качества

Измерять, а не оценивать глазом. `frame_qc.py compare` печатает по кадрам:

| Метрика | Норма | Тревожный знак |
|---|---|---|
| клиппинг (`clip_pct`) | ≤ 0,5 % | > 2 % → выбитые света |
| шум теней (`shadow_std`) | ≤ 0,03 и без цветового оттенка | растёт → цветной шум в тенях |
| контраст | 0,55–0,85 | < 0,4 → плоско, > 0,9 → жестко |
| средняя насыщенность | 0,20–0,30 | > 0,45 → громко, «трейлерно» |
| чёрная точка | 0,02–0,10 | 0,000 → выбито, без атмосферы |

Сравни вывод Resolve с одобренным превью: средняя абсолютная разница по каналам должна
остаться ниже ≈ 0,02. Больше — значит цепочка в Resolve не воспроизводит одобренный вид,
и чинить надо до того, как показывать кому-либо.

## 7. Контрольные кадры

Четыре сцены покрывают почти весь материал и сокращают ревью:

1. **тёмный / дальний** — поведение теней, шум, общее настроение;
2. **яркий блик** — спад света, glow на источнике;
3. **металл / отражение** — насыщенность кузова, как читаются отражения;
4. **крупный план** — резкость и сохранение деталей.

Извлекаются `frame_qc.py compare --frames ...`, собираются в контактный лист
(источник против результата) и отправляются **вместе с числами**.

Превью — **полный кадр**. Обрезанный кроп врёт: для крупных планов делается отдельный
зум на лицо.

---

## 8. Порядок утверждения

```
низкое разрешение (превью)
  → контрольный лист + метрики
  → явное «да/нет» заказчика
  → финальный рендер в согласованном разрешении
  → пост-проход (CDL + виньетка), чтобы финал совпал с одобренными кадрами
  → проверка
  → сдача мастера и компактных копий
```

Ни один шаг не перескакивает через предыдущий: без одобренного превью грейд не
переносится в Resolve.
