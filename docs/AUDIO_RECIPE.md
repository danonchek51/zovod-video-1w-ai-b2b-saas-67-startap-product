| Фильтр | Годится | Замечание |
|---|---|---|
| `arnndn` | **на этом материале вреден — отозван** | нейросетевое шумоподавление (RNNoise) съедает комнату и отдельные слова. Отзыв с замерами — §9 |

## 3. Рабочая цепочка

> **Пересмотрено 01.11.2026.** Прежняя цепочка (`arnndn`) **отозвана**: на материале
> тестовой сборки она съедала комнату и отдельные слова — заказчик услышал это как
> «пропал звук». Отзыв с замерами — §9. Ниже — цепочка, которой пересобран клип CLIP_A.

### Речь (нужен ровный уровень, комната обязана остаться)
```
highpass=f=80 , afftdn=nr=8:nf=-50 , loudnorm=I=-16:TP=-1.5:LRA=11[:linear=true|false]
```

### Проблемный клип: часть реплик провалилась
Если после цепочки видно, что отдельные слова тише остальных (проверять —
пословным RMS, §7), нужен **адаптивный подъём**, а не общий gain:
```
python tools/audio/build_clip_cut.py --src "<ПАПКА_ИСХОДНИКОВ>" --jobs jobs.json
                                          # гейт по огибающей 40/10 мс, потолок +9 дБ,
                                          # сглаживание 150 мс, гейт от шумового пола +6 дБ,
                                          # финал alimiter=-1.5 dBFS
```
Правило: поднимать только то, что ниже соседей; общий gain поднимет и шум, и
не даст нужного результата.

### Атмосфера/шум (речи нет, уровень трогать нельзя)
```
highpass=f=60 , afftdn=nr=8:nf=-50
```

### Порядок и почему
1. `highpass` — до шумоподавления, чтобы фильтр не тратил ресурс на гул.
2. `afftdn` — **мягкое** снятие шума пола (−2…−3 дБ), комната остаётся слышной.
3. `loudnorm` — выравнивание громкости, потолок пиков.
4. `deesser` — **не включать** (см. §5).
5. `arnndn` — **не включать** (см. §9).

## 4. Грабли ffmpeg (проверены, воспроизводятся)

| Грабля | Симптом | Решение |
|---|---|---|
| `anlmdn` падает | exit `0xC0000409`-семейства на **4 из 5** клипов; на уцелевшем клипе — шум снимает не хуже RNNoise, но WER 0,66 и окраска −494,7 Гц | не использовать вообще |
| `loudnorm` в динамическом режиме | **отдаёт звук на 192 кГц** вместо входной частоты | добавить `-ar 48000` и в цепочку, и на выход |
| путь к модели | «No option name near ...» | только относительный путь + `cwd` |
| разделитель опций фильтра | внутри фильтра — **двоеточие**, между фильтрами — запятая | `deesser=i=0.2:f=0.55`, а не `i=0.2,f=0.55` |
| `alimiter` | ограничивает **сэмплы**, не true peak | после него TP может быть +0,2 dBTP |
| `anlmdn` опции | `p`/`r` в секундах, диапазон 0,001–0,1 | `anlmdn=s=7:p=0.007:r=0.015:m=15` |
| `arnndn` + `deesser` | цепочка не парсится | двоеточие между опциями |
| **стерео прочитано как моно** | без `-ac 1` ffmpeg отдаёт **чередование каналов**: файл вдвое длиннее, тон «полуспид», все таймкоды врут вдвое | декодировать в моно **всегда** с `-ac 1`; сверять `len(x) == 48000 × duration` |
| `subprocess.run` без `input=` | ffmpeg читает пустой stdin и пишет **пустой WAV** (без ошибки) | передавать `input=` при записи в stdout |
| `-af` как входной опции | опция вывода, ffmpeg её не видит | `-af` ставить **после** `-i` |
| кириллица в пути к ffmpeg | PowerShell/ffmpeg ломает путь | кодировать путь UTF-8 |

**macOS:** те же фильтры и те же грабли; `cwd` задаётся через `cd <папка модели>`,
PowerShell-замены — `ls`, `grep`, `cp`, `rm`.

## 5. Почему деэссер не нужен

Замер полос на CLIP_A (средние окна, сумма энергии):

| Вариант | 0–150 Гц | 300–3400 Гц | 5–9 кГц | 5–9к/1–4к |
|---|---|---|---|---|
| исходник | 64,14 | 2154,95 | 13,80 | 0,0060 |
| RNNoise | 18,07 | 1647,61 | 5,90 | 0,0044 |
| RNNoise + deesser i=0,3 | 18,07 | 1647,07 | 5,83 | 0,0044 |
| RNNoise + deesser i=0,6 f=0,8 | 18,11 | 1564,52 | 3,29 | 0,0024 |

RNNoise **сам** снимает шипящие на −7,4 дБ. Деэссер при i=0,3 не даёт
измеримого эффекта (результат совпадает байт-в-байт с одним RNNoise), а при
i=0,6 срезает речевой диапазон 300–3400 Гц ещё на 5 % — голос глухнет.

## 6. Потолок true peak и почему чистая прибавка громкости не работает

У исходников **малый crest factor** (пики близко к 0 dBFS). Для речи −16 LUFS
при −1,5 dBTP недостижимо прибавкой громкости: 55 клипов из 71 упирались в
потолок пиков.

| Способ | Результат на C0095 | Вывод |
|---|---|---|
| линейный (`linear=true`) | I = −29,2 LUFS | не дотягивает до цели |
| `acompressor` + `alimiter` + gain | I = −22,1, **TP = +0,2 dBTP** | потолок пробит |
| **динамический (`linear=false`)** | **I = −19,4, TP = −1,5** | ✔ победитель |

Динамический `loudnorm` жертвует динамикой пиков, но не превышает потолок.
Проверка сохранности речи (WER по повторному распознаванию): динамический и
линейный дают **одинаковый** WER — 2,0 / 0,0 / 0,667 на трёх клипах.

Комбинированная схема (применена к материалу тестовой сборки):
- линейный путь там, где он попадал в цель (71 − 36 = 35 клипов);
- динамический там, где упирался в потолок (36 клипов);
- итог: разброс громкости речи **21 дБ → 4,3 дБ**, TP ≤ −1,5 у всех, клиппинг 0,00 %.

## 7. Как мерить (без догадок)

| Что | Чем |
|---|---|
| Интегрированная громкость, true peak | `ffmpeg -af ebur128=peak=true -f null -`, парсить `I:` и `Peak:` |
| Шум пола в паузах | 10-й перцентиль оконной RMS (окно 40 мс) |
| SNR | медиана активных окон минус пол |
| Клиппинг | доля сэмплов ≥ 0,999 |
| **Сохранность речи** | **повторное распознавание** (faster-whisper) и WER против исходника |
| Окраска тембра | сдвиг спектрального центроида |

Последние два — обязательны: без них «успешная» обработка может тихо убить
голос. Один и тот же клип с чистой прибавкой громкости уже даёт WER 0,07–0,6
просто из-за сдвига порога VAD — это шум метрики, а не порча.

## 10. Пересборка клипа по методу CLIP_A: обобщённый скрипт (02.11.2026)

### 10.1. Инструмент

`tools/audio/build_clip_cut.py` — обобщение одноразового прототипа «пересборка
по методу CLIP_A» на произвольный клип. Цепочка та же (§3, §9):

```
highpass=f=80 → afftdn=nr=8:nf=-50 → адаптивный подъём тихих слов (потолок +9 dB)
→ alimiter −1.5 dBFS → поиск пауз → вырезание из картинки И звука
```

Отличия от CLIP_A:

- порог паузы — «фон + 8 дБ» (в CLIP_A было +12): у CLIP_B/CLIP_C фон помещения
  громче, SNR клипа ≈ 16 дБ, при +12 дБ порог уходил в саму речь;
- пауза проверяется **пословной расшифровкой** (faster-whisper «small»);
- **дыра усекается вокруг слов**, а не отбрасывается целиком (см. §10.2);
- видео и звук могут иметь **разные in-point'ы** (у CLIP_B картинка с 190,
  звук с 405) — сегменты строятся для каждого окна независимо;
- вход и выход: `audio/proc_mux_fixed/<CLIP>_cut.mp4` + отчёт
  `audio/clip_bx_cut_plan.json`.

### 10.2. Почему дыра усекается, а не отбрасывается

Таймкоды ASR вероятностны: слово может стоять в 0,1 с от края паузы, и
перекрытия при этом нет. Жёсткий фильтр «задело слово → вырезаем паузу
целиком» терял 21 с мёртвого воздуха в CLIP_B. Правильное правило:

1. найти дыру (окно ниже «фон + MARGIN», ≥ 0,8 с);
2. вычесть из неё интервалы слышимых слов **с запасом 0,12 с**;
3. оставшиеся свободные куски ≥ 0,8 с — вырезать;
4. если свободного куска нет — дыру не трогать.

Проверка качества кандидата: сравнить его статистику (макс. уровень, p95,
доля времени выше порога) со статистикой уже вырезанных дыр. Кандидат
должен быть не хуже эталона — иначе это не пауза, а тихая речь.

### 10.3. Как проверить, что речь не потерялась

Сравнение по словам ASR ненадёжно (он по-разному сегментирует одни и те же
слова: «россии»/«россе», «уезжай»/«выезжай»). Работающая проверка —
**корреляция огибающих** пересборки с оригиналом по карте вырезов:
ожидается корреляция ≥ 0,99 при сдвиге < 1 кадра. Для CLIP_B/CLIP_C:
**0,993 / 0,992** (худший кусок 0,988), **сдвиг ≤ 0,030 с** (< 1 кадра).
