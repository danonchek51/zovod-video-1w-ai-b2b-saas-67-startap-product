# START_HERE — маршрут агента

Ты открыл папку с рабочей средой видеомонтажа. Ниже — маршрут, который приводит тебя
в рабочее состояние примерно за 15 минут. Выполняй по порядку; каждый шаг заканчивается
проверяемым результатом.

Не начинай монтаж, пока не пройдены шаги 1–4. Дальше — по `docs/WORKFLOW.md`.

---

## Шаг 1. Прочитать регламент (3 мин)

**Читай:** `AGENTS.md`

Это протокол: что можно и что нельзя, как мутировать таймлайн, когда брать точку
отката, что писать в отчёте. Ключевое, что нельзя пропустить:

* исходники — **только чтение**, всё производное пишется в рабочую папку;
* проект Resolve — **только через API**, руками по файлу проекта нельзя;
* **любой этап = вывод + точка отката**;
* перед мутацией — четыре пункта: доказательная база, кадровый diff, версия для
  отката, план проверки;
* «не проверено» ≠ «сделано»: в отчёте пишем числами и явно «проверено / не проверено».

**Результат шага:** ты можешь назвать четыре пункта правила мутации своими словами.

---

## Шаг 2. Понять, как устроен процесс (5 мин)

**Читай:** `docs/WORKFLOW.md`

Десять этапов: приёмка → инвентаризация → карта сцен → сборка → звук → цвет → контроль
качества → сдача. Для каждого этапа указано: что на входе, что делать, **какой гейт**
(условие, при котором этап считается закрытым), какие артефакты остаются и как откатить.

Если задача нестандартная, всё равно иди по этапам — гейты не выдумываются, а
подбираются под задачу.

**Результат шага:** ты знаешь, на каком этапе находишься и что считается его
выполненным.

## Шаг 3. Проверить машину (2 мин)

**Выполни:**

```bash
python tools/doctor.py
```

Читай строки `[ok] / [warn] / [FAIL]` и итоговый вердикт.

* `FAIL` — работать нельзя. Чини по `docs/ENVIRONMENT.md` (там есть установка под
  Windows и macOS и разбор типовых проблем).
* `warn` — работать можно, часть возможностей ограничена. Например, без ключа
  SFXMint доступна только библиотека CC0, а генерация звуков закрыта.

Если `doctor` ругается на ffmpeg — поставь его (`brew install ffmpeg` на macOS,
`winget install Gyan.FFmpeg` на Windows) и прогони снова.

**Результат шага:** получено «ВЕРДИКТ: среда готова» (или понятный список того,
что доделать).

## Шаг 4. Зафиксировать пути (1 мин)

**Выполни:**

```bash
python tools/env_paths.py set src_root    "<папка с исходниками>"
python tools/env_paths.py set project_root "<папка проекта>"
python tools/env_paths.py show
```

Автодетект обычно справляется, но исходники и рабочую папку лучше указать явно:
все инструменты берут пути отсюда, и ничего не пишется наружу.

**Результат шага:** `env.json` существует, `src_root` указывает на материал.

## Шаг 5. Принять материал (3 мин)

**Выполни:**

```bash
python skills/davinci-resolve-workbench/scripts/media_probe.py <папка с исходниками>
```

Получишь инвентаризацию: контейнер, кодек, разрешение, fps, кадры, длительность, цвет,
палитра по каждому файлу. Плюс подсветку расхождений: разные fps, лог-исходник,
клипы без звука, битые файлы.

**Ничего не монтируй, пока не прочитал таблицу.** Один пропущенный рассинхрон fps
ломает весь монтаж позже.

**Результат шага:** таблица материалов и список замечаний.

## Шаг 6. Задать заказчику недостающие вопросы (2 мин)

Одним списком, не по одному:

1. **Что должно измениться** и **что обязано остаться нетронутым**.
2. **Целевой результат**: хронометраж, площадка публикации, разрешение, нужен ли
   отдельный «чистый» звук.
3. **Границы**: можно ли резать материал, переставлять блоки, терять фрагменты реплик.
4. **Сроки и гейт**: сколько вариантов до какого этапа.

Ответы, которые уже есть в материале, не спрашивай. Неизвестное — спрашивай сразу
в одном списке, а не по очереди.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Resolve не отвечает на скрипты | `docs/FAILURE_MODES.md` — раздел про краш и модалки |
| «скрипт вернул True, но ничего не изменилось» | `docs/RESOLVE_RECIPE.md` — DRX: флаг ≠ результат |
| цвет стал красным после `SetCDL` | `docs/FAILURE_MODES.md` §26 — грейд только через LUT |
| Resolve умер после `ApplyGradeFromDRX` | `docs/FAILURE_MODES.md` §27 — DRX на клипах под переходом |
| `SetLUT` вернул `False` | `docs/FAILURE_MODES.md` §28 — три разные причины |
| звук «пропал» в кусках | `docs/AUDIO_RECIPE.md` — разбор про шумоподавление |
| таймкоды не бьются с картинкой | `docs/MEASUREMENT.md` — синхронизация по огибающей |
| Python ругается на кодировку | `docs/FAILURE_MODES.md` — BOM и `utf-8-sig` |
| нужно откатить | `python tools/checkpoint.py list`, затем `restore <метка>`; состояние Resolve — `tools/resolve_checkpoint.py` |

---

**Ключевая установка пакета:** лучше потратить 15 минут на чтение регламента и один
замер, чем час переделывать монтаж, потому что «так красивее». Все решения в этом пакете
принимаются числами и откатываются одной командой.
