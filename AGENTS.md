# AGENTS.md — протокол работы агента в этой среде

Прочитай целиком до начала работы. Этот файл — регламент: он не переписывается по ходу
работы, меняются `docs/` и контекст проекта.

**Проверенная автором конфигурация:** Windows 10/11 x64, DaVinci Resolve Studio 21.1.1,
ffmpeg 9.x, Python 3.9+ (проверено на 3.14), Node 18+.
Для macOS подготовлены эквивалентные пути, но живой прогон на macOS не выполнялся —
учитывай это, проверяя среду через `tools/doctor.py` первым делом.

---

## 1. Железные правила

1. **Исходники — только чтение.** Никогда не перезаписывать, не переносить, не «поправить
   на месте». Любое производное (кадры, звук, LUT, отчёты, рендер) пишется в рабочую
   папку проекта.
2. **Проект Resolve — только через API.** Никаких ручных правок файла проекта, никакого
   «просто открою .drp в блокноте».
3. **Правило этапа:** любой этап = **вывод + точка отката**. Снимок делается
   `tools/checkpoint.py save`, откат — `restore`.
4. **Один вариант за раз.** Следующий вариант или этап — только после одобрения
   предыдущего. Не строить «на всякий случай» три версии.
5. **Не проверено — значит не сделано.** В отчёте писать «проверено / не проверено»
   явно. Числа вместо «на глаз»: RMS, LUFS, доля клиппинга, покадровая раскладка.
6. **Права — по умолчанию запас.** Режим «внутренний показ» — можно CC-BY и бесплатные
   сервисы. Публикация в соцсетях ведомств — только CC0/PD, платные подписки или Pro.
   Подробности — `docs/LEGAL_ASSETS.md`.
7. **Опасные вызовы — по необходимости.** Обычная работа с Resolve идёт через безопасный
   канал; файловые/сетевые/процессные операции — через небезопасный, и это
   проговаривается заказчику.
8. **Не додумывать.** Если результат не измерен — так и сказать. Ссылки на
   несуществующие файлы, треки, ID запрещены.
9. **Заказчик может править проект параллельно.** Не перестраивай его работу; перед
   финальной фиксацией перечитывай состояние таймлайна заново.
10. **Инструмент — сначала на одном объекте.** Новый скрипт (особенно мутирующий Resolve)
    сначала прогоняется на одном клипе с чтением обратно и только потом идёт в пайплайн.
    Массовая операция без пробного объекта — это 56 повторов одной ошибки.
11. **Не строить процесс на вызове, который роняет программу.** Если вызов крашит Resolve
    (`ApplyGradeFromDRX` на клипах под переходом), он не идёт в цикл: ищем другой путь
    (3D-LUT) и фиксируем грабли в `docs/FAILURE_MODES.md`.
12. **Если работа заказчика пропала — сказать, а не восстанавливать по памяти.** После
    краша его правок может не быть вовсе; честное «не найдено» полезнее выдуманного
    «восстановлено».

## 2. Правило мутации (главное)

Операция разрешена **только если ты можешь показать все четыре пункта**:

| # | Что показать | Пример |
|---|---|---|
| 1 | **Доказательная база** — на каких материалах/замерах основано решение | «клиппинг 14,36 % → 0,00 %, RMS 1,26/255» |
| 2 | **Кадровый diff** — что именно изменится | «38 клипов, CDL + LUT, таймлайн 90000…106116» |
| 3 | **Версия для отката** | метка точки отката из `tools/checkpoint.py list` |
| 4 | **План проверки после записи** | «15 контрольных кадров 4K + RMS против расчёта» |

Нет любого из четырёх — **стоп, спросить**.

### Порядок работы в сессии

1. **Первое действие — read-only.** Отчёт: Resolve запущен? какой проект, таймлайн, fps,
   таймкод, раскладка дорожек, что доступно из API. Ничего не мутировать.
2. **Перед мутацией** — показать текущее состояние и намерение (таблица выше).
3. **Dry-run** для диапазонных операций, обрезков, перемещений, массовых правок.
4. **Явные source-ranges и позиционированные append.** Вставка по playhead ненадёжна —
   использовать append с явным `recordFrame`/`trackIndex`.
5. **Новая версия таймлайна перед каждой нетривиальной правкой** — не переписывать рабочий.
6. **После каждой мутации — структурная проверка:** gaps/overlaps, длительность против
   ожидания, карта треков, спот-чек маркеров. Инструмент — `tools/verify_timeline.py`.
7. **Исходники иммутабельны.** Прокси, релинк, транскод, удаление — только по явному
   одобрению.

## 5. Правила оформления

* **Язык:** общение и документация — русский. Идентификаторы, код, промты для внешних
  сервисов — английский.
* **Контекст проекта** (`templates/PROJECT_CONTEXT.md`) — **append-only**: добавляем новый
  раздел, не переписываем старые. Раздел = этап или исследование. В конце раздела —
  «что сделано / что проверено / что осталось».
* **Артефакты** именуются с префиксом этапа: `stage<N>_…`, `pass<N>_…`, `cmp_…`.
  Дата в имени — `YYYYMMDD`. Пробелы и кириллица в именах, которые уходят в Resolve, —
  недопустимы.
* **Превью — полный кадр.** Обрезанный кроп врёт; для крупных планов — отдельный зум
  на лицо.
* **Правовые пометки** — на каждый сторонний ассет: лицензия, источник, что нужно
  (атрибуция / ничего / подписка).

## 6. Границы среды (проверено, а не «вроде бы»)

* **Ноды цветокора не создаются через API** (`AddNode`/`AddSerial`/`AddParallel`
  отсутствуют). Поэтому грейд, который можно выразить одной кривой, делается **3D-LUT'ом**
  через `SetLUT` — это единственный безопасный путь наката на рабочем таймлайне.
* **`ApplyGradeFromDRX` роняет Resolve** на клипах, перекрытых переходом (воспроизведено
  4 раза за одну сессию). На клипе без перехода применяется, но **возвращает `True` и
  тогда, когда картинка не изменилась**. Обязательно сверять состав тулов и рендер;
  на рабочем таймлайне многоузловой DRX накатывать вручную в Color page.
* **`SetCDL` красит клип в красный** и молча отвергает словарь с лишним ключом — цвет
  через него не наносится. Рецепт обхода — `docs/COLOR_LOOK.md` §2.1.
* **Fusion-комп не попадает в экспорт кадра** — рендерится только цветовая ветка.
  Зерно и текстура видны только в рендер-джобе.
* **Компьютерного зрения в инструментах нет** — «найти взрыв в картинке» невозможно.
  События задаются маркерами, списком кадров или транскрипцией.
* **Таймкоды ASR вероятностны.** Слова — с точностью до слова, не до кадра: резать по
  границам фраз, а не по таймкоду слова.
* **Append при коллизии не перезаписывает, а сдвигает и обрезает** — звук может молча
  укоротиться. Всегда сверять длину размещённого айтема.
* **Расхождение стаба и рантайма:** стаб `.pyi` неполон, а неизвестный метод в этом
  биндинге возвращает `None` вместо исключения. Проверять фактический API через `dir()`.
* **Стерео, прочитанное как моно, удваивает таймкоды** — всегда декодировать с `-ac 1`.
* **BOM в `.py` ломает `exec`** внутри Resolve. Если пишешь файл для запуска в Resolve —
  снимай BOM.

## 7. Память проекта

Всё, что узнал о конкретном проекте, пиши в **контекст проекта**
(копия `templates/PROJECT_CONTEXT.md` в рабочей папке проекта), а не в этот файл.
Контекст — append-only: новый раздел внизу, старые не переписываются. Так история
решений остаётся читаемой, и агент, пришедший позже, не повторяет пройденное.

Формат раздела: **этап или исследование → вход → что сделано → что проверено → что
осталось**. Внутри — числа, а не ощущения.
