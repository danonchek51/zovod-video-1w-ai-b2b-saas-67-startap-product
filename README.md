# ZOVod Video — переносимая рабочая среда видеомонтажа

Это самодостаточная рабочая среда для видеомонтажа в DaVinci Resolve, упакованная так,
чтобы её можно было **передать товарищу** и он начал работать сразу: без установки
специальных скиллов, без настройки, без «поищи в интернете, как это делается».

Собеседник открывает папку, скармливает её своему агенту (достаточно ввода текста
и картинки) — и агент сразу компетентен: знает рецепты звука, знает грабли скриптового
API Resolve, умеет мерить и проверять, умеет откатывать.

| `tools/` | ~40 рабочих инструментов (Python 3, кроссплатформенно) | Инвентаризация, ASR, звук, замеры, грейд, DRX, проверки |

Полный каталог инструментов — `tools/MANIFEST.md`.

## Быстрый старт

### 1. Проверить, что машина готова

```bash
python tools/doctor.py
```

Врач проверит Python и модули, ffmpeg/ffprobe, DaVinci Resolve (установлен / запущен /
доступен ли скриптовый API), папку LUT, Node и вендорные кодеки, свободное место и ключ
SFXMint. Печатает `[ok] / [warn] / [FAIL]` и итоговый вердикт. **Красное — сначала чиним,
потом работаем.** Подробности и установка — `docs/ENVIRONMENT.md`.

### 2. Зафиксировать свои пути (один раз)

```bash
python tools/env_paths.py set src_root   "D:/Shoot/raw"        # исходники (только чтение)
python tools/env_paths.py set project_root "D:/Shoot/project"  # рабочий проект
python tools/env_paths.py set work_root  "D:/Shoot/project/work"
python tools/env_paths.py show
```

Автодетект покрывает стандартные установки; ручная правка нужна для портативных сборок
и сетевых дисков. Приоритет: переменная окружения `ZOVOD_*` > `config/env.json` > автодетект.

### 3. Скормить папку агенту

Дайте агенту прочитать `START_HERE.md` — это готовый маршрут: что читать, что запустить,
в каком порядке. Дальше он сам дойдёт до приёмки материала.

### 4. Принять материал

```bash
python skills/davinci-resolve-workbench/scripts/media_probe.py <папка с исходниками>
```

Папка обходится рекурсивно, каждый файл пробируется: контейнер, кодек, разрешение, fps,
число кадров, длительность, цветовые теги, палитра (чёрная точка, контраст, насыщенность,
шум в тенях, доминирующие оттенки). На выходе — таблица инвентаризации и подсветка
расхождений (разные fps, лог-исходник, клип без звука, референс другого разрешения).

## Правило, которое стоит прочитать до работы

> **Исходники — только чтение.** Любое производное (кадры, звук, LUT, отчёты, рендер)
> пишется в рабочую папку проекта. Никогда не «поправить на месте».
>
> **Проект Resolve — только через API.** Никаких ручных правок файла проекта.
>
> **Любой этап = вывод + точка отката.** Снимок делается `tools/checkpoint.py save`,
> откат — `restore`.
>
> **Не проверено — значит не сделано.** В отчёте пишем «проверено / не проверено» явно,
> числами (RMS, LUFS, доля клиппинга, покадровая раскладка), а не «на глаз».

Полный регламент — `AGENTS.md`.

## Что НЕ внутри (и почему)

Пакет — это **среда**, а не чей-то конкретный проект. Поэтому здесь нет:

* наших исходных материалов, таймлайнов, бинов Resolve, файлов `.drp`;
* точек отката и архивов прошлых правок;
* отчётов, транскриптов и contact sheets конкретных сцен;
* нашей переписки и истории работы над чужим видео.

Зато есть **метод и проверенные грабли**: способы обработки звука, приёмы пересборки
клипа с вырезанием пауз, методика проверки «речь не потеряна», поведение скриптового
API Resolve 21.1.1, ловушки ffmpeg, PowerShell, кодировок и файловых обходов.

## Платформы

Пакет работает на **Windows** и **macOS**. Весь код — Python 3.9+, без платформенных
зависимостей; пути не зашиты, а вычисляются (`tools/env_paths.py`).
Различия, список пакетов и то, что нужно доустановить, — `PLATFORMS.md`.

Проверено автором на Windows 10/11 x64 + DaVinci Resolve Studio 21.1.1.
Для macOS подготовлено по тем же правилам, но **живого прогона на macOS не было** —
это честно отмечено в `docs/ENVIRONMENT.md`; первое, что должен сделать получатель,
— прогнать `tools/doctor.py`.
