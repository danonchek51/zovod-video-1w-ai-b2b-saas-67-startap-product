# CHANGELOG

## 1.1.0 — 2026-11-06

Опыт, накопленный на живом монтаже (проект 3840×2160, 25 fps, Resolve 21.1.1): цветокор
на 56 клипов подан через 3D-LUT, ни одного краша Resolve, каждый шаг закрыт замерами.

### Добавлено

* `tools/color/make_cdl_luts.py` — сборка .cube (33³) по спецификации ASC-CDL
  (`Slope/Offset/Power/Saturation`) в гамма-домене. Пишет в стандартном порядке
  (красный — самая быстро меняющаяся ось) и проверяет результат сразу после записи.
* `tools/color/verify_lut.py` — самопроверка .cube против исходной CDL-математики.
  Отдельно распознаёт **переставленные R и B** — ошибку, которая не видна глазом
  (картинка не красная, но не та) и стоила полного цикла перенаката.
  Дополнительно сверяет файл с ffmpeg `lut3d`.
* `tools/color/apply_lut_grade.py` — батчевый накат LUT на клипы таймлайна
  **внутри Resolve**: копирование кубов в папку LUT Resolve под ASCII-именами,
  `RefreshLUTList()`, выбор клипа по (трек, старт) **и имени** (переход может иметь
  тот же стартовый кадр), чтение обратно по каждому клипу, режим dry-run.
* `tools/resolve_checkpoint.py` — точка отката **состояния Resolve**: `SaveProject` +
  `ExportProject` (`.drp`) + копия живой `Project.db` + манифест.
  Раньше пакет умел откатывать только рабочую папку.
* `docs/COLOR_LOOK.md` §2.1 — «быстрый путь: грейд целиком в LUT»: порядок
  (спецификация → сборка → самопроверка → установка → накат → проверка) и таблица
  A/B-проверки грейда рендером.

### Исправлено

* `skills/davinci-resolve-workbench/references/resolve-api-gotchas.md`:
  * `SetLUT` **принимает только путь внутри папки LUT Resolve** — абсолютный путь
    в другое место возвращает `False` (раньше в документе было написано обратное);
  * `pm.ExportProject(name, path)` **работает** (раньше было записано, что метод не
    доступен);
  * `ApplyGradeFromDRX` не «не делает ничего», а **роняет Resolve** на клипах,
    перекрытых переходом;
  * `SetCDL` красит клип в красный и **молча отвергает словарь с лишним ключом**;
  * добавлены: `RefreshLUTList()` после копирования, принудительное перечитывание
    изменённого куба через `SetLUT(1, "")`, переход как источник `GetNodeGraph() = None`,
    `GetSettings()` вместо `GetSetting()`, неизменяемая выходная гамма, Project Manager
    впереди блокирует мутации, протухший `project` после перезапуска, Qt-диалог краша.
* `docs/FAILURE_MODES.md` §26–30 — красный каст `SetCDL`, краш на `ApplyGradeFromDRX`,
  три причины `SetLUT = False`, попадание грейда в переход, «Resolve перестал выполнять
  мутации».
* `skills/davinci-resolve-workbench/scripts/resolve_bridge.py` — скрипты читаются как
  `utf-8-sig`: файл, записанный через PowerShell `Set-Content -Encoding UTF8`, больше
  не падает с `invalid non-printable character U+FEFF`.
* `tools/MANIFEST.md`, `START_HERE.md` — новые инструменты и маршрут агента к ним.

### Проверено на живом проекте

* накат 56/56 клипов, 42 цвета, 0 крашей Resolve;
* read-back графа: 56/56 — ровно один узел, ровно один инструмент `LUT: …`, посторонних
  грейдов 0;
* A/B-рендер: MAE «с LUT / без LUT» = 0,0788 (грейд меняет 99,4 % пикселей),
  расхождение с расчётной CDL = 0,0070, восстановление LUT = 0,0000 (бит-в-бит);
* красный каст: R − max(G, B) ≤ +0,041 на всех блоках, кроме самого ТВ-ролика (+0,174).

## 1.0.0 — 2026-11

Первая упаковка рабочей среды видеомонтажа в переносимый вид.

### Добавлено

**Ядро пакета**
* `README.md` — что это, быстрый старт, что внутри и что не внутри.
* `START_HERE.md` — маршрут агента на 15 минут (правило мутации → воркфлоу →
  врач среды → пути → приёмка материала → вопросы заказчику).
* `AGENTS.md` — протокол работы: железные правила, правило мутации (4 пункта),
  порядок работы в сессии, границы среды (что проверено, что не умеет).
* `PLATFORMS.md` — Windows и macOS: пути, установка, платформенные особенности.
* `LICENSE` — MIT для кода пакета + перечень третьестороннего кода.

**Документация (`docs/`)**
* `ENVIRONMENT.md` — установка и проверка среды на обеих платформах, разбор проблем.
* `WORKFLOW.md` — десять этапов монтажа: вход, гейт, артефакты, откат, типовые ошибки.
* `EDITING_PLAYBOOK.md`, `AUDIO_RECIPE.md`, `RESOLVE_RECIPE.md`, `FAILURE_MODES.md`,
  `SFX_RECIPE.md` — перенесены из рабочей среды и обобщены (проект, клипы, люди,
  абсолютные пути заменены плейсхолдерами; числа и грабли сохранены).
* `COLOR_LOOK.md` — работа с цветом: DRX, power window, LUT, контрольные кадры.
* `MEASUREMENT.md` — методика измерений и форма отчётов.
* `LEGAL_ASSETS.md` — лицензии, атрибуция, режимы публикации.

**Инструменты (`tools/`)**
* `doctor.py` — проверка среды: Python, модули, ffmpeg/ffprobe, Resolve (установлен /
  запущен / скриптовый API), LUT, Node, вендорные кодеки, диск, ключ SFXMint.
* `env_paths.py` — единый конфиг путей: приоритет env > `config/env.json` > автодетект;
  поиск Resolve, ffmpeg, LUT на Windows и macOS.
* `start_resolve.py` — запуск Resolve (обычная установка, портативная сборка, macOS `.app`).
* `dismiss_dialogs.py` — снятие модалок, блокирующих скриптовый API (замена
  Windows-only `.ps1`; работает на обеих платформах).
* `checkpoint.py`, `new_project.py`, `verify_timeline.py`, `media_probe.py`,
  `frame_qc.py`, `resolve_bridge.py`, `resolve_doctor.py` — точки отката, скаффолд
  проекта, структурная проверка, инвентаризация, контроль кадров, мост к Resolve.
* `audio/`, `asr/`, `inventory/`, `scene/`, `color/`, `sfx/` — обработка и замеры звука,
  пересборка клипа с вырезанием пауз, проверка речи по огибающим, транскрипция,
  инвентаризация и тряска, карта сцен, LUT/DRX/контактные листы, звуковые эффекты.
* `MANIFEST.md` — каталог инструментов с командами и отметкой «проверен / не проверен».

**Стороннее**
* `skills/davinci-resolve-workbench/` — вендоренный скилл Resolve (SKILL.md,
  4 reference-документа, 5 скриптов).
* `vendor/resolve-mcp-advanced/` — MIT-кодеки DRX/DRP/DRT и conform-QC.

**Шаблоны и примеры**
* `templates/` — контекст проекта (append-only), `verify_job.json`, конвенции имён,
  чек-лист этапа, чек-лист выдачи.
* `examples/` — синтетические примеры отчётов и спецификаций (без реальных данных).

### Не вошло (осознанно)

Материалы, таймлайны, бины, `.drp`, точки отката, отчёты, транскрипты, contact sheets
конкретного проекта и история работы над ним. Пакет содержит среду, метод и грабли,
а не чужой проект.

### Известные ограничения

* Живой прогон инструментов на **macOS не выполнялся** — инструкции и пути подготовлены
  по правилам, но первый шаг получателя на macOS: `python3 tools/doctor.py`.
* Поведение API проверено на DaVinci Resolve **21.1.1**; на других версиях сверяться с
  `docs/RESOLVE_RECIPE.md`.
* Рендер-джобы и Fusion-композиции проверяются только внутри Resolve, не скриптом.
