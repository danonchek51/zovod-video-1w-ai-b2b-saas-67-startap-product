# templates/deliverable_checklist.md — что должно лежать в выдаче проекта

**Когда.** Этап «Сдача» (`docs/WORKFLOW.md`, этап 9) — **после** всех правок.

**Зачем.** Выдача — это не «файлы в папке», а набор, в котором заказчик может
разобраться сам: открыть, проверить, откатить и понять, что осталось на его
решение.

**Связанные документы:** `docs/WORKFLOW.md`, `docs/MEASUREMENT.md`,
`docs/LEGAL_ASSETS.md`, `templates/stage_checklist.md`, `templates/naming.md`,
`tools/check_deliverables.py`, `tools/checkpoint.py`.

---

## 1. Состав выдачи

| # | Что | Где лежит | Обязательно |
|---|---|---|---|
| 1 | **Финальный таймлайн** (Resolve) | проект Resolve в сдаче | да |
| 2 | **Выгрузка проекта** `.drp` | `11_delivery/` | да |
| 3 | **Финальные рендеры** (версионированные) | `11_delivery/` или `07_renders/` | да |
| 4 | **Превью для согласования** | `11_delivery/` | да |
| 5 | **Отчёты измерений** (JSON) | `03_analysis/`, `08_audio/`, `10_qc/` | да |
| 6 | **Точки отката** (до и после) | `_checkpoints/` + `manifest.json` | да |
| 7 | **`LICENSES.md`** | корень проекта | да (если есть сторонние ассеты) |
| 8 | **Контекст проекта** `PROJECT_CONTEXT.md` | корень проекта | да |
| 9 | **Манифест сдачи** | `11_delivery/` | да |
| 10 | **Отчёт заказчику** (что изменилось, цифры, что осталось на его решение) | `11_delivery/` | да |
| 11 | Исходники проекта (конфиг, планы, карты) | `00_brief/`, `05_blueprints/` | желательно |

## 2. Проверка состава

```
[ ] python tools/check_deliverables.py — расхождений нет
[ ] Все файлы, на которые ссылаются документы, существуют
[ ] Числа в отчётах и в документах сходятся (нет «разнобоя» цифр)
[ ] Ничего лишнего: черновики и отладочные файлы не попали в выдачу
```

---

## 3. Проверка по пунктам

### 3.1. Таймлайн и проект

```
[ ] Таймлайн в Resolve открывается и воспроизводится
[ ] Структурная проверка пройдена: delta_s = 0,000 с, gaps = 0, overlaps = 0
[ ] Карта дорожек совпадает с планом (нет «лишних» дорожек)
[ ] Имя таймлайна и fps соответствуют выдаче
[ ] Маркеры расставлены по плану
[ ] .drp выгружен ПОСЛЕ всех правок (не до)
[ ] Проверено, что .drp открывается: проект загружен, таймлайн на месте
```

### 3.2. Рендеры и превью

```
[ ] Финальный рендер лежит с версией в имени (v<N>_...), дата в имени
[ ] Превью отличается от финала: облегчённый, с метками времени
[ ] Превью показывает проблемные места с таймкодами
[ ] Разрешение, fps и таймкод финала совпадают с заданием
[ ] Файл открывается и проигрывается целиком (проверено, а не «должен быть в порядке»)
```

### 3.3. Отчёты

```
[ ] Отчёт по звуку: rms, пик, клиппинг, тишина, речь — с нормами и вердиктами
[ ] Отчёт по таймлайну: длительность, дорожки, дыры, наложения, маркеры
[ ] Отчёт по корреляции огибающих (если пересобиралась речь)
[ ] Каждый отчёт — JSON формы «метрика / значение / норма / вердикт»
[ ] В отчётах нет провалов; если есть — они не «закрыты», а перемерены
[ ] Явно перечислено, что НЕ проверено
```

### 3.4. Точки отката

```
[ ] Есть точка отката ДО сдачи (состояние до последних правок)
[ ] Есть финальная точка отката (состояние на момент сдачи)
[ ] manifest.json на месте и читается
[ ] Проверено, что откат восстанавливает состояние (выборочно — на копии)
```

### 3.5. Права на ассеты

```
[ ] LICENSES.md существует и перечисляет все сторонние ассеты
[ ] Для каждой позиции: автор, название, лицензия, ссылка
[ ] Лицензии проверены по источнику (не «по памяти»)
[ ] Атрибуция внесена в титры/концовку, если этого требует лицензия
[ ] В кадре нет следов чужих материалов (водяные знаки, логотипы, чужая музыка)
```

### 3.6. Контекст проекта и отчёт заказчику

```
[ ] PROJECT_CONTEXT.md содержит все разделы этапов, ничего не переписано
[ ] Последний раздел закрыт блоком «что сделано / что проверено / что осталось»
[ ] Отчёт заказчику: что изменилось, цифры, что осталось на его решение, сроки
[ ] «Проверено» и «не проверено» разделены явно
```

---

## 4. Что считается «готово»

Проект **сдан**, когда одновременно:

1. Все пункты §3 закрыты, а `tools/check_deliverables.py` не находит расхождений.
2. Есть **две** точки отката: до сдачи и финальная, обе читаются.
3. Финальные файлы **воспроизводятся** (проверено открытием и просмотром,
   а не «должны работать»).
4. Каждое утверждение о качестве подтверждено **числом и отчётом** в проекте.
5. `LICENSES.md` на месте и закрывает все сторонние ассеты.
6. Контекст проекта дописан: по нему видно, что сделано, что проверено
   и что осталось.
7. Отчёт заказчику отделён от внутренних заметок и отвечает на вопрос
   «что изменилось и что решать вам».

### Чего недостаточно для «готово»

| Недостаточно | Почему |
|---|---|
| «Файл отрендерил» | рендер не равен проверенный результат |
| «Послушал — нормально» | без числа это не проверка (`docs/MEASUREMENT.md`) |
| «Таймлайн собрал» | без структурной проверки неизвестно, есть ли дыры |
| «Почти всё» | у выдачи нет состояния «почти»: есть «сдано» и «не сдано» |
| Один отчёт на весь проект | отчёт должен закрывать конкретный аспект (звук / таймлайн / речь) |
