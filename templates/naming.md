# templates/naming.md — соглашения об именах файлов и каталогов

**Зачем.** Имя файла — это первая строка отчёта. По имени видно, что это,
на каком этапе, когда сделано и для чего. Разные агенты в разные дни должны
называть одно и то же одинаково, иначе через месяц никто не найдёт нужный
файл, а «новый финал» будет лежать рядом со «старым финалом».

**Связанные документы:** `docs/MEASUREMENT.md` (отчёты измерений),
`docs/WORKFLOW.md` (этапы), `templates/stage_checklist.md`,
`templates/deliverable_checklist.md`, `tools/checkpoint.py` (точки отката).

---

## 1. Общие принципы

| Правило | Почему |
|---|---|
| Имя = **префикс** + **содержание** + **суффикс** (+ дата) | по имени видно тип и этап |
| Только латиница, цифры, `_`, `-`, `.` | одинаково работает в Resolve, ffmpeg, скриптах, MCP |
| Один смысл — одно имя | два разных файла не должны отличаться одним символом |
| Версия в имени, а не «final_final2» | см. §5 |
| Дата — в имени артефакта, если он мог быть перезаписан | §3 |

---

## 2. Префиксы

| Префикс | Что это | Пример |
|---|---|---|
| `stage<N>_` | результат **этапа** N (монтаж, звук, цвет, сдача) | `stage4_audio_mix_report` |
| `pass<N>_` | промежуточный **проход анализа** (инвентарь, транскрипция, кадры) | `pass3_transcripts` |
| `cmp_` | **сравнение** двух вариантов (до/после, вариант A против B) | `cmp_grade_a_b` |
| `v<N>_` | версия **рендера** | `v3_rough` |

`<N>` — порядковый номер этапа или прохода, без нулей: `stage4_`, `pass3_`.

### 2.1. Что НЕ является префиксом

| Плохо | Почему | Хорошо |
|---|---|---|
| `final.mp4` | «final» бывает тройной | `v3_rough_20260101.mp4` |
| `new_audio.wav` | «new» перестаёт быть новым через неделю | `stage4_audio_mix_20260101.wav` |
| `tmp2.png` | вне контекста не восстановить | `cmp_grade_a_b_20260101.png` |

---

## 3. Дата и время

| Формат | Когда | Пример |
|---|---|---|
| `YYYYMMDD` | дата в имени артефакта | `stage4_audio_mix_report_20260101.json` |
| `YYYYMMDD_HHMMSS` | когда в имени нужен порядок внутри дня | `stage4_music_variant__20260101_101530` |

* Дата — **в конце** имени, перед расширением.
* Разделитель даты и времени — `_`, разделитель метки точки отката — `__`
  (так формирует `tools/checkpoint.py`).
* Дата **не нужна**, если файл не перезаписывается: `LICENSES.md`,
  `project.json`, `PROJECT_CONTEXT.md`.

---

## 4. Суффиксы

| Суффикс | Что за файл | Пример |
|---|---|---|
| `_cut` | пересобранный (вырезанный) фрагмент | `clip_0001_cut.mp4` |
| `_preview` | превью для согласования (лёгкое, с водяным знаком, не финал) | `stage6_preview_20260101.mp4` |
| `_report` | отчёт измерений (JSON или текст) | `stage4_audio_mix_report_20260101.json` |
| `_plan` | план: раскладка, карта, смета, ТЗ | `stage5_music_plan_20260101.json` |

Суффиксы комбинируются: `stage4_clip_0001_cut_report_20260101.json` —
отчёт по пересборке клипа.

---

## 5. Версии

* Версионирование — **в имени файла**, номер без нулей: `v1_`, `v2_`, `v3_`.
* Правка того же этапа = новая версия с новой датой, а не перезапись:
  `stage4_audio_mix_20260101.wav` и `stage4_audio_mix_20260104.wav` — два
  разных состояния, оба сохранены.
* Перезаписывать артефакт можно только тогда, когда **до него есть точка
  отката** (`tools/checkpoint.py`).

## 6. Каталоги

### 6.1. Раскладка проекта

| Каталог | Что внутри |
|---|---|
| `00_brief/` | бриф, ТЗ, правки заказчика |
| `01_media/` | манифест исходников (не копии файлов) |
| `02_proxies/` | прокси (только после одобрения) |
| `03_analysis/` | профили, транскрипции, опорные кадры, замеры |
| `04_selects/` | отобранные сцены, сюжетная карта |
| `05_blueprints/` | планы монтажа, музыкальные блоки |
| `06_timelines/` | описания таймлайнов, листы монтажа |
| `07_renders/` | рендеры (версионированные) |
| `08_audio/` | дорожки, микс, отчёты громкости |
| `09_graphics/` | титры, графика, шаблоны |
| `10_qc/` | QC-отчёты, контрольные кадры |
| `11_delivery/` | финальные файлы и манифест сдачи |
| `_checkpoints/` | точки отката (zip + `manifest.json`) |
| `logs/` | логи агента |

### 6.2. Имена каталогов

* Латиница, нижний регистр, `_`, без пробелов.
* Порядковый префикс (`01_`, `02_`) — **фиксированный**: новый каталог
  добавляется в конец списка, существующие не перенумеровываются.

## 7. Запреты в именах

| Запрещено | Пример неправильно | Почему ломается |
|---|---|---|
| Пробелы | `stage 4 audio mix.wav` | разные скрипты и MCP-вызовы путают аргументы |
| Кириллица | `этап4_микс.wav` | файлы, которые идут в Resolve, ломают перекрёстные ссылки и часть утилит |
| Спецсимволы | `stage4:audio.wav`, `stage4#1.wav` | невалидны в shell, в JSON-ключах, в путях |
| Двойные подчёркивания внутри имени | `stage4__audio.wav` | `__` зарезервирован под метку точки отката |
| Пробелы в именах файлов, которые идут в Resolve | — | Resolve, ffmpeg и скрипты по-разному экранируют |

**Правило для Resolve:** всё, что попадает в медиапул или в таймлайн
(клипы, аудио, изображения, шрифты, LUT), называется **латиницей без
пробелов**. Русские названия допустимы в документах и отчётах.

---

## 8. Точки отката

Метка точки отката — это имя артефакта без расширения:

```
stage4_music_variant__20260101_101530
```

`tools/checkpoint.py` сам дописывает `__<YYYYMMDD_HHMMSS>` при снимке,
поэтому в метке **не** пишется дата вручную.

---

## 9. Шпаргалка

```
stage<N>_<что>_<суффикс>_<YYYYMMDD>.<ext>     результат этапа
pass<N>_<что>_<YYYYMMDD>.<ext>                промежуточный анализ
cmp_<что>_a_b_<YYYYMMDD>.<ext>                сравнение
v<N>_<что>_<YYYYMMDD>.<ext>                   рендер
<что>_cut.<ext>                               пересобранный фрагмент
<что>_preview_<YYYYMMDD>.<ext>                превью
<что>_report_<YYYYMMDD>.json                  отчёт
<что>_plan_<YYYYMMDD>.json                    план
```
