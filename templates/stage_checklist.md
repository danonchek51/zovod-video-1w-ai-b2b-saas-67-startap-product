# templates/stage_checklist.md — чек-лист этапа

**Один этап = вывод + точка отката.** Чек-лист распечатывается (или
копируется в раздел `PROJECT_CONTEXT.md`) и заполняется **по факту**:
незакрытый пункт — это не «почти готово», а открытая работа.

**Связанные документы:** `AGENTS.md` (правило мутации), `docs/WORKFLOW.md`
(порядок этапов), `docs/MEASUREMENT.md` (чем мерить), `docs/FAILURE_MODES.md`
(типовые отказы), `templates/naming.md` (имена), `templates/PROJECT_CONTEXT.md`
(куда писать результат).

## 1. ДО — до первой мутации

### 1.1. Read-only инспекция (ничего не меняем)

```
[ ] Resolve запущен, открыт нужный проект
[ ] Имя проекта, имя таймлайна, fps, таймкод — записаны
[ ] Карта дорожек: сколько видео, сколько звука, что на каждой
[ ] Состояние на момент старта зафиксировано (что уже есть на таймлайне)
[ ] Исходники доступны только на чтение (правило: не перезаписывать)
[ ] Окружение проверено: python tools/doctor.py
```

### 1.2. Правило мутации — все четыре пункта

> Ни один пункт не может быть пустым. Если хотя бы один не сформулирован —
> мутация не начинается.

| # | Пункт | Заполнить |
|---|---|---|
| 1 | **Доказательная база** — на каких материалах и замерах основано решение | <замеры: клиппинг 14,36 % → 0,00 %, RMS 1,26/255 — свои числа> |
| 2 | **Кадровый diff** — что именно изменится | <число клипов, что с ними, диапазон таймлайна в кадрах> |
| 3 | **Версия для отката** — метка точки отката | <метка> |
| 4 | **План проверки** — как проверяем результат | <метрики, нормы, инструменты> |

```
[ ] 1. Доказательная база — записана
[ ] 2. Кадровый diff — записан
[ ] 3. Версия для отката — метка названа
[ ] 4. План проверки — метрики и нормы названы
```

### 1.3. Точка отката (снимок ДО работы)

```
[ ] Снимок сделан ДО первой мутации
```

```powershell
python tools\checkpoint.py --root <корень_проекта> save <метка> "<что делаем>"
```

Список точек отката:

```powershell
python tools\checkpoint.py --root <корень_проекта> list
```

Откат (если этап пошёл не туда):

```powershell
python tools\checkpoint.py --root <корень_проекта> restore <метка>
```

### 1.4. До мутации ещё

```
[ ] Dry-run выполнен для диапазонных операций (обрезание, перемещение, массовые правки)
[ ] Новый таймлайн (копия) создан — рабочий не переписывается
[ ] Явные source-ranges и позиционированные append; вставка по playhead не используется
[ ] Один вариант за раз: следующий вариант — только после одобрения предыдущего
```

## 2. ПОСЛЕ — после мутации

### 2.1. Структурная проверка таймлайна

```
[ ] Проверка таймлайна выполнена после записи (не до)
[ ] delta_s = 0,000 с
[ ] Дыры (gaps) = 0 на каждой дорожке
[ ] Наложения (overlaps) = 0 (переходы Cross Fade не считаются наложением)
[ ] Айтемы нулевой длины = 0, айтимы вне таймлайна = 0
[ ] Карта дорожек совпадает с планом
[ ] Маркеры на месте (спот-чек по плану)
```

Проверка выполняется внутри Resolve (MCP `davinci-resolve`, `run_script_unsafe`):
`tools/verify_timeline.py` с файлом ожиданий `templates/verify_job.json`
(копия рядом со скриптом или в текущем каталоге запуска).

### 2.2. Измерения

| Что | Метрика | Норма | Инструмент | Отчёт |
|---|---|---|---|---|
| <...> | <...> | <...> | <...> | `<путь>` |

```
[ ] Все метрики плана проверки измерены
[ ] У каждой метрики есть норма и вердикт
[ ] Провалы не «закрыты словами» — возвращаемся к шагу и меряем заново
```

### 2.3. Визуальная проверка

```
[ ] Контрольные кадры отсняты и просмотрены (полный кадр, без кропа)
[ ] Крупные планы проверены отдельным зумом на лицо
[ ] В кадре нет чужих водяных знаков, логотипов, служебных надписей
```

### 2.4. Точка отката на «после»

```
[ ] Снимок после этапа сделан (метка <метка>_done)
```

```powershell
python tools\checkpoint.py --root <корень_проекта> save <метка>_done "<что сделали>"
```

### 2.5. Контекст проекта

```
[ ] В PROJECT_CONTEXT.md добавлен новый раздел (append-only, старые не правились)
[ ] Раздел заканчивается блоком «что сделано / что проверено / что осталось»
[ ] В блоке «что проверено» — числа и пути к отчётам
[ ] Явно записано, что осталось НЕ проверенным
```

## 4. Итог этапа

```
[ ] Все пункты «ДО» закрыты
[ ] Все пункты «ПОСЛЕ» закрыты
[ ] Проверки пройдены, отчёты лежат в проекте
[ ] Есть точка отката до и после
[ ] Контекст проекта обновлён
[ ] Остаток один вариант, следующий этап не начат без одобрения
```

**Этап закрыт, когда подписаны все пункты и в контексте проекта есть раздел
с числами и отчётами. Не «почти готов» — а закрыт.**
